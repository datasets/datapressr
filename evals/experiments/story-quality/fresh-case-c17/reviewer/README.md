## Staging prerequisite

`../case.preparation.json` deliberately contains a null input commit and zero execution budget: this is a preparation descriptor, not a runnable harness case. The existing harness stages inputs with `git archive` and requires an input commit ancestral to main. After independent review and accepted integration, `.9.11` must set that real commit in a separate execution manifest and validate through `validateCase`/existing stage machinery. Do not fabricate a commit or invoke writer commands to test it. The allowed writer inputs are exactly `../inputs/` plus the frozen prompt, never this reviewer directory, exposure log, reconstruction checks or manifest. The source chart in inputs is a reconstruction fixture; the future protocol should decide uniformly whether to expose it to both arms before any writing. Any change to permitted-input policy needs a new manifest, no silent change.
