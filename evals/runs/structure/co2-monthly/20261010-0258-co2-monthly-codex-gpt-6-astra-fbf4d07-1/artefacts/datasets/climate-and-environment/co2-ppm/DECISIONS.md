# Decisions

- **Monthly key:** Use `date` in `YYYY-MM-01` form as the primary key, replacing separate year and month columns. Alternatives were a composite `(year, month)` key or a `yearmonth` field. A first-of-month label follows the requested full-date convention and works with date-aware consumers; the schema explicitly says it is a monthly label, not a daily measurement. Profiling found 821 non-blank, unique year/month pairs.
- **Resource and field names:** Use `data/co2-monthly.csv`, resource `co2-monthly`, and fields `date`, `decimal_year`, `average_ppm`, `deseasonalized_ppm`, `measurement_days`, `standard_deviation_ppm`, `uncertainty_ppm`. Alternatives were retaining abbreviated source names or a shorter concentration-only table. These names expose units and meanings, retain every source measurement and diagnostic, and avoid confusing day counts with a trend. Retain source decimal years rather than dropping or recalculating them because they carry the source's time representation independently of the monthly label.
- **Numeric serialization:** Validate numbers but write the original trimmed numeric strings. Converting to JavaScript numbers before writing would retain numeric values here but remove trailing zeros; preserving the strings keeps the supplied decimal precision visible without rounding.
- **Missing diagnostics:** Recognize exactly the observed per-column sentinels: `-1` for day count, `-9.99` for standard deviation, and `-0.99` for uncertainty. Alternatives were treating all negatives as missing or accepting generic example sentinels such as `-9.99` for uncertainty. The archived header and profile support these specific values; unexpected negatives fail the build for investigation. Actual zeros, including `0.00` uncertainty, remain values. The concentration columns contain no sentinels and are required; future missing concentrations require an explicit metadata and build revision.
- **Interpolation and site information:** Preserve all source months and concentration values, document interpolation and site changes in metadata, and add no inferred interpolation or station column. Alternatives were dropping suspect months, assigning an interpolation boolean from negative diagnostics, or assigning one site to every month. The header describes paired negative diagnostics for interpolated NOAA months, but December 1975 and April 1984 have negative standard deviation and zero uncertainty; earlier Scripps negatives mean unavailable diagnostics. A definitive interpolation flag would overstate what this snapshot establishes, and July 2023 can include both sites.
- **Reuse terms:** Use the source header's own title, `USE OF NOAA GML DATA`, as the license name, link to the source file containing those terms, and reproduce the terms in `license_notes`. Alternatives were asserting a public-domain or Creative Commons license, or leaving licensing unspecified. The header expressly permits free availability and requests credit but does not name an SPDX license; no broader legal declaration is supported by the offline evidence. Credit NOAA GML and C. David Keeling/Scripps in metadata without inventing a citation DOI or uncertainty definition.
- **Build guards:** Require the exact source header, eight cells per row, plain numeric unquoted input, valid calendar months and day counts, matching calendar/decimal years, and unique chronological contiguous months. Pin this snapshot's count and endpoints to 821 rows, March 1958 through July 2026. Alternatives were sorting silently, accepting gaps, or checking only schema types. These guards catch column changes, duplicates, malformed data and truncation; a later snapshot needs a deliberate coverage update. Resolve paths relative to `build.ts` rather than the working directory so the same offline command works from either the dataset directory or repository root.
- **Supporting files:** Include `.datahubignore` excluding the raw archive, validator, build script, agent instructions and decision log from publication, while retaining all of them in Git. Alternatively these implementation files could be uploaded with the data; they are not published resources. Copy the root instructions through the dataset conventions section into the dataset's `AGENTS.md`, ending before `Workflow`, because the supplied root file has no explicit repo-only marker. The repository's workflow/skill installation instructions would not be self-contained in the dataset directory.
