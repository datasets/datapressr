# Decisions

Decisions made while structuring `co2-ppm` that the task, `AGENTS.md` and the `structure` skill did not settle.

1. **Date as one `date` column typed `yearmonth` (`YYYY-MM`), and `year` and `month` dropped.** Alternatives: `YYYY-MM-01` typed `date` (what the older community `co2-ppm` does), or keeping the source's separate `year` and `month` integers. Why: `AGENTS.md` lists `YYYY-MM-DD` and `YYYY` but nothing for monthly data. `YYYY-MM` is ISO 8601, the validator checks it, and DataHub charts accept it as a `group`. A `-01` day would suggest the value is for the 1st, when NOAA centres it on mid-month. `year` and `month` only repeat `date`.
2. **Kept `decimal_date`.** Alternative: drop it as derivable. Why: it is NOAA's own mid-month timestamp, not a simple function of the month that a reader could rebuild, and it is handy for plotting and fitting.
3. **Column names:** `average` → `co2_ppm`, `deseasonalized` → `co2_deseasonalized_ppm`, `ndays` → `n_days`, `sdev` → `daily_sdev_ppm`, `unc` → `uncertainty_ppm`. Alternatives: keep NOAA's names, or match the community dataset's (`Average`, `Trend`...). Why: the house rule is snake_case with units where they're ambiguous. The skill says to use our own names unless we're deliberately matching a ground truth, and this task isn't. "ppm" is NOAA's own unit label (mole fraction in dry air).
4. **Sentinels mapped to empty cells, one list per column:** `ndays` −1, `sdev` −9.99, `unc` −0.99, and −99.99 for `average`/`deseasonalized` (none in this snapshot). Any other negative value fails the build. Alternatives: emptying every negative value, or keeping the sentinels as they are. Why: the file header documents negative ndays/sdev/unc as "no information". −99.99 is NOAA's long-standing missing marker for the mole fractions and costs nothing to cover. Failing on any other negative means an undocumented code can't get through quietly.
5. **`unc = 0.00` kept verbatim for 1975-12 and 1984-04, and documented in the field description.** Alternatives: treat 0.00 as missing as well. Why: NOAA doesn't document 0.00 as a sentinel, and the skill says to keep the source's values rather than guess. It does look suspicious (both months have no sdev, and 1975-12 also has no ndays), so the description warns readers.
6. **No `is_interpolated` flag.** Alternative: derive one from the negative sdev/unc markers. Why: for the SIO period (1958-03 to 1974-04) those markers mean "no information", not "interpolated", so a flag would be wrong for 194 rows. In the NOAA era the markers don't match NOAA's own description cleanly (point 5). Instead, the `co2_ppm` description explains the situation.
7. **Numbers written as the source's own text** (e.g. `0.00`, `2026.2083`), checked as numbers but not re-serialised from floats. Alternative: `Number()` → `String()`. Why: re-serialising drops trailing zeros (so the stated precision is lost) and can change how a value is printed. The skill says to keep the source's precision.
8. **Output file and resource name `co2-ppm-monthly` (`data/co2-ppm-monthly.csv`).** Alternative: `co2-mm-mlo` (the source name) or `data.csv`. Why: it follows the skill's `<thing>-<frequency>` pattern for resource names and leaves room for an annual or weekly resource later.
9. **License recorded as `NOAA-GML-data-use`, linked to the data page, with the header's terms summarised in `title`.** Alternatives: `CC0-1.0` / "US Government Work, public domain", or leaving it out. Why: there's no SPDX id, and the file itself says only "freely available" and asks for credit. It doesn't say "public domain", so I didn't claim it. `AGENTS.md` says to use the license's own name and a link when there's no SPDX id. The terms are only quoted in the file header, so I linked the landing page given in the task rather than a policy URL I couldn't check offline.
10. **Three `sources`:** the CSV URL, the landing page, and Scripps (for 1958-03 to 1974-04, from the URL in the file header). Alternative: the NOAA file alone. Why: the file says the pre-May-1974 values are Scripps measurements, so that provenance belongs in the metadata.
11. **Build assertions:** an exact header match, 8 cells per row, no quotes or CRs, contiguous ascending months, `decimal_date` inside its month, CO2 in a plausible range (250–600 ppm), `n_days` an integer of at most 31, the first row anchored (1958-03 = 315.71), and at least 821 rows. Alternative: only the header assert the skill names. Why: these cheaply catch the ways a refresh could break things. Before committing I checked three mutations against the build (reordered header columns, a deleted month, an undocumented negative value), and each one failed it.
12. **Plain `split(",")` parser, no dependency.** Alternative: `csv-parse`. Why: the source has no quoting, and the build checks that (it fails if a `"` appears). This is the case the skill names for a plain split.
13. **No step 7 adversarial review.** Alternative: a self-review. Why: the skill names this dataset (`co2-ppm`, a single CSV with a `#` preamble) as not needing one. The blind-run notes only ask for self-review in the story skill. I didn't fill the gap with a self-review labelled as independent.
14. **Added `.datahubignore`** (excludes `archive/`, `scripts/`, `DECISIONS.md`) **and copied the repo `AGENTS.md` into the dataset directory.** Alternative: produce only the four files listed in the task. Why: `AGENTS.md` lists both in the dataset structure and says to exclude raw downloads from publishing. The repo `AGENTS.md` has no "repo-only marker", so I copied the whole file. `sync-dataset-agents.mjs` isn't in this workspace.
15. **Copied `num` and `toCsv` into `build.ts` from the skill's idioms module** rather than importing them. Why: the skill says to copy them, because datasets are independent repos.
