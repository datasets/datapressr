# Decisions

Decisions made while structuring `co2-ppm` that the task, `AGENTS.md` and the validator did not settle.

1. **Sentinels become empty cells.** `ndays = -1`, `sdev = -9.99` and `unc = -0.99` are written as empty cells, as the house rule on missing values asks. Alternatives: keep the negatives (the source's own convention, which is what `github.com/datasets/co2-ppm` does), or keep them and add a flag column. Why: the file header says negatives mean "no information" or "interpolated", so they are missing values, not measurements. Any mean or minimum taken over a column with `-9.99` in it would be wrong.
2. **`unc = 0.00` next to a missing `sdev` is treated as missing.** This affects two rows: 1975-12 (`ndays -1, sdev -9.99, unc 0.00`) and 1984-04 (`ndays 2, sdev -9.99, unc 0.00`). Alternatives: keep `0.00` verbatim, or drop the rows. Why: the uncertainty is derived from the daily spread, so it cannot be a real zero when the spread is unknown. Its pairing with a sentinel `sdev`, plus 1975-12 being an interpolated month (`ndays -1`), marks it as a placeholder. The rule in `build.ts` is narrow: it only fires when `sdev` is the sentinel and `unc` is exactly zero. The field description names both months. 1984-04 keeps `days_measured = 2`, which is a real count.
3. **One `date` column (`yearmonth`, `YYYY-MM`) replaces `year` + `month`, and is the primary key.** Alternatives: keep the integer `year` and `month` with a composite key, or use a full date such as `YYYY-MM-01` or `YYYY-MM-15`. Why: it follows the ISO 8601 house rule without inventing a day-of-month. It is a type the DataHub simple charts accept on the x-axis, and the validator checks it.
4. **`decimal date` is kept as `decimal_date`.** Alternative: drop it because it is derivable from the month. Why: it is the source's own mid-month timestamp, and plots against it are the standard way the series is drawn.
5. **Column names.** `average` → `co2_ppm`, `deseasonalized` → `co2_deseasonalized_ppm`, `ndays` → `days_measured`, `sdev` → `daily_sdev_ppm`, `unc` → `monthly_mean_unc_ppm`. Alternatives: lower-case the source names unchanged (`average`, `sdev`, …), or reuse the `datasets/co2-ppm` names (`Average`, `Trend`, …). Why: the house rule asks for snake_case with units where a value would otherwise be ambiguous. The descriptions keep the original source names so that users can map between the two.
6. **Numbers are copied as strings, not re-formatted.** Alternative: parse to float and re-print. Why: this keeps the source's fixed precision (1959-08's `314.80` stays `314.80`, not `314.8`) and guarantees byte-identical output. `build.ts` still checks every value against a numeric pattern and fails on anything unexpected (header change, extra column, gap or reorder in months, unknown negative), instead of passing it through silently.
7. **No derived columns.** I added no `interpolated` flag and no `program` (SIO/NOAA) or `site` (Mauna Loa/Maunakea) column. Alternative: derive them from the header prose. Why: the header gives the SIO period and the Maunakea period as prose (the Maunakea switch-back is "July 4, 2023", mid-month). It also says interpolation cannot be told apart from "no information" for the SIO months. A derived column would claim more than the source gives, so these facts go in the dataset `description` instead. They could be added at the `enrich` stage.
8. **License entry.** I used `name: "NOAA-GML-data-use"` with the terms summarised in `title` and linked to the data page. Alternatives: `CC0-1.0`, or the Open Definition id `other-pd` (NOAA data is a US federal government work). Why: no SPDX id applies, and the file's own terms say "freely available" and ask for credit and citation without naming a licence. `AGENTS.md` says to use the license's own name and a link in that case. I did not assert CC0 or public domain on NOAA's behalf.
9. **Sources.** I listed three: the CSV URL with the retrieval date (2026-08-30), the landing page, and the Scripps URL given in the header for the 1958–1974 data. Alternative: list only the CSV URL. Why: the pre-May-1974 part of the series comes from Scripps, and the header names that origin.
10. **File and resource name: `data/co2-mm-mlo.csv` / `co2-mm-mlo`.** Alternatives: `data/co2-ppm.csv`, or `monthly.csv`. Why: it keeps the source file's identity (`co2_mm_mlo`: monthly mean, Mauna Loa) in URL-safe form. That leaves room for sibling resources from the same NOAA page (annual mean, weekly, global) without a rename.
11. **No `views` yet.** Alternative: add a line chart now. Why: charts belong to the `enrich` stage in the lifecycle, and `structured` does not require them.
12. **`.datahubignore` excludes `archive/` and `scripts/`.** Alternative: also exclude `build.ts` and `DECISIONS.md`. Why: `AGENTS.md` says to exclude raw downloads, and the validator is tooling. The build script and decisions are small and document provenance, so they are published.
13. **`AGENTS.md` is copied whole into the dataset directory.** Alternative: copy only the part above the "repo-only marker". Why: the root `AGENTS.md` mentions that marker, but it does not contain it, and `scripts/sync-dataset-agents.mjs` is not in this workspace. Copying everything is the reversible choice.
14. **Adversarial review is done as a self-review.** The source has a `#` comment preamble ahead of the header, and `build.ts` parses it with its own logic. That arguably counts as "a spreadsheet with a preamble", which triggers the review requirement in the definition of done. The `structure` skill's step 7 checklist is not in this workspace (`skills/` is absent), and no independent reviewer is available. Alternative: treat the file as a plain CSV and skip the review. Why: being conservative costs little. The record is below.
