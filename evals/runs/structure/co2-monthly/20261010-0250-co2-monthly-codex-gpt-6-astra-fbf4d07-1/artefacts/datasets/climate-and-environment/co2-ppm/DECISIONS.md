# Decisions

1. **Time key:** Use `date` as the primary key, representing each month as `YYYY-MM-01`, instead of separate year/month key columns or a `yearmonth` field. This follows the requested full ISO date convention and supports ordinary date tooling; the schema explicitly says the first day is a period label, not a daily observation. Year and month remain recoverable without redundant columns. Profiling found 821 distinct, nonblank year/month pairs.
2. **Resource and field names:** Name the sole resource `co2-monthly`, file `data/co2-monthly.csv`, and fields `date`, `decimal_year`, `average_ppm`, `deseasonalized_ppm`, `ndays`, `sdev_ppm`, and `uncertainty_ppm`. Alternatives were a generic file name and longer expanded diagnostic names. These names identify the frequency and units while preserving the source terminology; field descriptions expand the abbreviations. Use the title “Mauna Loa Monthly Atmospheric CO2” to state the station and frequency.
3. **Retained information:** Retain both concentration series, the source decimal date, and all three diagnostics instead of publishing only the mean or recomputing decimal dates. They contain useful source information, and the decimal date is distinct from the first-day period label. Preserve numeric strings, including trailing zeros, rather than reformatting or rounding numbers.
4. **Missing-value mapping:** Map `-1` only in `ndays`, `-9.99` only in `sdev`, and `-0.99` only in `unc` to empty cells. Also recognize the skill's `-99.99` concentration sentinel in average and deseasonalized values (absent from this snapshot). Reject other negative numbers instead of blanking every negative value or accepting new sentinels silently. The observed blank counts become 195, 196, and 194 respectively for the diagnostic columns. Retain the two literal `0.00` uncertainty values: December 1975 and April 1984. A negative standard deviation does not justify emptying a different field.
5. **Interpolation and station attribution:** Keep all source months, including source-interpolated values, without adding inferred interpolation or per-month station flags. Alternatives were dropping interpolations or classifying them from negative diagnostics. Those diagnostics also mark unavailable Scripps statistics and are not consistently paired; the header also describes a within-month station transition. Preserve those qualifications in dataset and field descriptions instead of asserting more precise classifications than the archive supports.
6. **Terms and provenance:** Record the header's own “USE OF NOAA GML DATA” terms, link to the source file containing them, and transcribe the terms into license metadata. Alternatives were assigning CC0/public-domain status or another standard license, none of which the supplied header establishes. Include both supplied source URLs, retrieval date, Scripps attribution, and the Maunakea substitution note. Do not invent a citation DOI or uncertainty confidence level unavailable in the archive.
7. **Build safeguards:** Require numeric unquoted cells, the exact eight-column source header, valid months, unique consecutive chronological keys, decimal dates within their stated year, and day counts within their calendar month. Pin completeness to this snapshot's 821 rows and March 1958–July 2026 endpoints; future snapshots require a deliberate update. Alternatives were sorting silently, accepting gaps, or using only schema checks. Failing explicitly catches shifted columns, malformed values, duplicate months, dropped rows, and truncation without repairing source data speculatively. Resolve paths relative to the script rather than the working directory so the same command also works from the repository root.
8. **Publication support files:** Add `.datahubignore` excluding the archive, validator scripts, build script, agent instructions, and decision log; these remain committed for reproducibility but are not dataset resources. An alternative was publishing the support files alongside the CSV. Copy the root `AGENTS.md` verbatim because the task requests dataset instructions and this workspace supplies no separate dataset template or repo-only marker. Do not add charts or other optional enrichment beyond the requested structuring work.
9. **Verification:** In addition to the required validator and double build, compare every row and retained value using Python's independent standard-library CSV reader. An alternative was checking only sample rows. This small file permits exhaustive comparison without a runtime build dependency. The skill's step 7 explicitly exempts this single-file NOAA CSV case from independent adversarial review; do not claim a reviewer approval or apply the unrelated story-review checklist. No dependency test suite is needed for this dependency-free build.
