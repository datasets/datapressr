# Decisions

Decisions made while structuring `co2-ppm` that the task, `AGENTS.md` and the validator did not settle.

1. **Sentinels become empty cells.** The source writes "no value" as `-1` (ndays), `-9.99` (sdev) and `-0.99` (unc). I blank them, following the AGENTS.md rule that missing is a genuinely empty cell. Alternatives: keep the sentinels and declare them in `schema.missingValues` (faithful to the source, but every consumer has to know the codes, and three different codes in three columns), or drop the columns. Blanking keeps the information without the trap of a `-9.99` ppm being averaged in.
2. **An uncertainty of `0.00` is treated as missing too.** Two rows (1975-12 and 1984-04) have `unc = 0.00` with `sdev = -9.99`. I blank them (the build treats `unc <= 0` as missing). Alternative: keep `0.00` as a real value. A monthly mean can't have zero uncertainty, and in both rows the standard deviation it would be computed from is missing, so `0.00` reads as another "not available" code. Documented in the field and resource descriptions.
3. **1984-04 keeps `days_measured = 2`.** Its ndays is a real count; only sdev and unc are missing. Alternative: treat the whole row's statistics as missing. No reason to throw away a valid count.
4. **No interpolation or provenance flag column.** The header says interpolated NOAA months are marked by negative stdev/uncertainty, and that SIO months (1958-03 to 1974-04) carry negatives because there is no information. I describe this in the resource and field descriptions rather than adding `interpolated`, `data_source` (SIO/NOAA) or `site` (Mauna Loa/Maunakea) columns. Alternatives: add those derived columns. An `interpolated` flag can't be computed for SIO months (the source can't tell), and the source/site splits are header prose, not data; adding them is enrichment and would be my reading rather than the source's. In this snapshot an empty `days_measured` from May 1974 onward identifies the one interpolated NOAA month (1975-12).
5. **One `date` column (`yearmonth`, `YYYY-MM`) replaces `year` and `month`.** AGENTS.md asks for ISO 8601 dates. Alternatives: keep `year` and `month` as integers (closest to the source, but not an ISO date); a full `YYYY-MM-DD` on the 1st or 15th of the month (it invents a day the source doesn't have, and the values are centred on the month, not its first day). `yearmonth` is exact, is the primary key, and DataHub can chart it.
6. **`decimal_date` kept.** It duplicates `date` but is the source's own mid-month timestamp, handy for plotting and regression. Alternative: drop it as redundant.
7. **Column names.** `average` → `co2_ppm`, `deseasonalized` → `co2_deseasonalized_ppm`, `ndays` → `days_measured`, `sdev` → `daily_std_dev_ppm`, `unc` → `uncertainty_ppm`, `decimal date` → `decimal_date`. Snake case with units, per AGENTS.md. I kept the source's American spelling "deseasonalized" so it maps to NOAA's documentation. The unit "ppm" is not stated in the file; it is NOAA's documented unit for this series and is in the dataset's name.
8. **Numbers are copied verbatim as text**, not parsed and re-printed. Keeps the source's precision (two decimals, four for decimal dates) and makes the output byte-stable. Alternative: parse and format with fixed precision. Verbatim is simpler and can't introduce float-formatting drift.
9. **The build fails loudly on surprises.** It checks the exact header, a strict row pattern, months 1–12, and that months run consecutively with no gaps or duplicates. Alternative: a lenient parser that skips odd rows. A source format change should stop the build, not silently change the data.
10. **Licence entry.** The file states no formal licence, only that the data are "made freely available to the public" with a request for credit and citation. There is no SPDX id, so per AGENTS.md I used the terms' own name (`NOAA-GML-data-use`, with the credit request in the title) and linked the NOAA data page given in the task. Alternatives: `CC0-1.0`/`PDDL-1.0` or "US Government work, public domain". NOAA data are generally US federal works, but the file doesn't say so and the 1958–1974 part is Scripps data, so I didn't assert a public-domain status the source doesn't state.
11. **Three `sources`.** The NOAA file URL (with retrieval date), the NOAA data page, and the Scripps CO2 program URL named in the header for the 1958–1974 data. Alternative: NOAA file only. The header asks for credit and names Scripps as the originator of the early data.
12. **Output file name `data/co2-mm-mlo.csv`, resource name `co2-mm-mlo`.** Mirrors the source file name, hyphenated to be URL-safe. Alternative: `monthly.csv` / `co2-ppm-monthly`.
13. **Title.** "CO2 PPM - Trends in Atmospheric Carbon Dioxide (Mauna Loa, monthly)", following NOAA's own page title. Alternative: a shorter "Mauna Loa monthly CO2".
14. **`.datahubignore` excludes `archive/` and `scripts/`.** The raw download and the validator aren't part of the published dataset. `build.ts`, `DECISIONS.md` and `AGENTS.md` are not excluded: they document how the data were made. Alternative: publish only `datapackage.json` and `data/`.
15. **`AGENTS.md` copied in whole.** AGENTS.md says to copy "everything above the repo-only marker", but this copy has no marker and `scripts/sync-dataset-agents.mjs` isn't in the workspace, so I copied the whole root file. Alternative: copy nothing, or hand-trim to the dataset sections.
16. **Optional schema extras.** I added `required` on the four always-present columns, `minimum: 0` on the three statistics, and per-field titles and descriptions. The validator doesn't check `minimum`, but it documents intent. Alternative: types and the primary key only.
17. **No adversarial review under step 7 of the `structure` skill.** The skill isn't in this workspace. Going by the trigger in AGENTS.md, this source is a regular CSV with a `#` comment preamble and one fixed layout, read with a strict regex. It's not a PDF, HTML, prose or a multi-layout spreadsheet, and it's one document. I judged the review not to be triggered. As a substitute I cross-checked independently: a separate Python `csv` reader of the raw file compared all 821 rows value by value with `data/co2-mm-mlo.csv`. Every non-blank value matches, and every blank corresponds to a source value ≤ 0. Range of `co2_ppm`: 312.42 (1958-10) to 432.34 (2026-05). Alternative: treat the comment preamble as a "preamble" trigger and run a self-review. Recorded here so a reviewer can disagree.
